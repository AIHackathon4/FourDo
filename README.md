# FourDo · 관심을 도전으로, 도전을 실행으로

공모전 공고와 내 프로필을 넣으면, 그 공고를 **내 상황에서 어떻게 준비하면 되는지** 알려 주는 웹 서비스입니다.
인공지능학과 대학 연합 해커톤 4조 FourDo의 프로젝트입니다.

**서비스 써 보기**: https://demo-vm58.onrender.com/

## 어떤 문제를 푸는가

대학생은 대외활동이 필요하다고 느끼지만 실제 도전으로 이어지는 비율은 낮습니다.

| 조사 결과 | 수치 | 출처 |
|---|---|---|
| 졸업 전 대외활동이 필요하다고 답한 대학생 | 65.5% | 대학내일20대연구소, 2026 |
| 2025년 대외활동 참여율 | 44.4% | 대학내일20대연구소, 2026 |
| 공모전 참여율 | 39.9% | 대학내일20대연구소, 2024 |
| 소극적 구직의 가장 큰 이유가 '역량 부족에 따른 추가 준비' | 37.5% | 한국경제인협회, 2025 |
| 학기 중 아르바이트 병행 | 43.6% | 한국대학신문, 2025 |

공고는 제출물만 나열할 뿐 필요한 역량 수준과 작업량은 알려 주지 않습니다. 수업, 시험, 아르바이트를 빼고 남는 시간으로 끝낼 수 있는지도 공고를 보는 시점에는 따져 보기 어렵습니다.

> **핵심 문제**: 공모전에 관심이 있어도 공고만으로는 내 역량과 시간으로 무엇을 어디까지 준비해야 하는지 알 수 없어, 도전할 만한 공모전도 포기한다.

처음에는 참여 가능 여부만 판정하면 된다고 보았습니다(이 저장소의 PODO 프로토타입). 그러나 "가능하다"는 판정만으로는 무엇부터 시작할지 알 수 없어서, 서비스의 중심을 판정에서 **개인별 준비 계획**으로 옮겼습니다.

## 무엇을 해 주는가

**입력**: 공고(링크 또는 모집요강)와 프로필(학년·전공, 주당 가용 시간, 바쁜 일정, 보유 역량, 관련 경험, 팀 상황). 에브리타임 시간표 캡처를 올리면 수업 시간도 반영합니다.

| 제공 결과 | 내용 |
|---|---|
| 조건 비교 | 참가 자격, 팀 인원, 제출물을 내 상황과 비교해 충족, 주의, 부족, 확인 필요로 표시 |
| 시간 비교 | 준비에 필요한 시간과 마감까지 쓸 수 있는 시간 |
| 막는 요소와 해결 방법 | 도전을 막는 요소와 대안 |
| 실행 계획 | 이번 주 할 일, 주차별 작업, 하루별 할 일. 시험 주간과 수업 시간은 피해서 배치 |
| 개인화 비교 | 프로필 없이 분석한 결과와 내 결과를 나란히 표시 |
| 내 도전 기록 | 로그인하면 분석한 공고를 기록으로 저장 |

**AI와 규칙의 역할 분담**

| 담당 | 맡는 일 |
|---|---|
| AI (Google Gemini 4 Hydrogen) | 공고 정보 추출, 조건과 프로필 비교, 필요 시간 추정, 계획 작성, 시간표 캡처 읽기. 공고에 없는 내용은 확인 필요로 둔다 |
| 규칙 | 입력 검증, 오늘 날짜 전달, 남은 날짜와 가용 시간 계산, 수업 시간과 겹치는 할 일 제거 |
| 사람 | 확인 필요 조건을 직접 확인하고 도전 여부를 결정 |

분석은 AI 호출 한 번으로 처리합니다. 응답이 없으면 Gemini 3.8 Flash로 전환해 다시 시도합니다.

## 평가

실제 공모전 공고 28건에 평가용 유저 페르소나를 짝지은 **152건**으로 평가했습니다. 같은 사례를 같은 AI 모델과 같은 지시문으로 두 번 실행해, 개인화 정보를 넣었을 때와 공고만 넣었을 때를 비교했습니다. 생성된 계획은 AI가 아닌 규칙으로 채점했습니다.

| 지표 | 공고만 넣었을 때 | 개인화 정보를 넣었을 때 |
|---|---|---|
| 시간·일정 제약을 어긴 계획 | 25% (38건) | 13% (20건) |
| 시험 기간에 할 일을 넣은 계획 (시험 일정이 있는 28명) | 39% (11명) | 14% (4명) |
| 무리한 계획을 '부족' 표시 없이 제시 | 17% (26건) | 9% (13건) |
| 경계 사례 12건 중 '부족' 표시 없이 무리한 계획 제시 | 6건 (50%) | 0건 (0%) |

- 공고만 넣었을 때 제약을 어긴 38건 중 23건이 개인화 정보를 넣자 해소됐고, 새로 위반이 생긴 사례는 5건입니다.
- 같은 사례끼리 짝지어 비교한 검정(McNemar)에서 제약 위반 감소는 통계적으로 유의했습니다(p<0.001).
- 마감일은 152건 중 147건을 정확히 추출했습니다(97%).

평가용 유저 페르소나 224명은 AI 없이 공개 통계(대학알리미 학과별 재적 현황, 대학내일20대연구소 조사, 한국대학신문 조사, 각 대학 학사일정)와 규칙으로 만들었습니다. 평가 대상인 AI가 평가 데이터까지 만들면 결과를 신뢰하기 어렵기 때문입니다.

이 평가는 계획이 학생의 시간과 일정을 지키는지를 확인한 것입니다. FourDo가 실제 공모전 지원을 늘리는지는 출시 후 지원 여부와 계획 완료율을 기록해 확인할 계획입니다.

## CUBIG Syntitan 활용

팀이 만든 평가 데이터의 사각지대를 외부 도구로 점검하는 데 두 제품을 썼습니다.

| 구분 | Syntitan 활용 전 | Syntitan 활용 후 |
|---|---|---|
| 평가 데이터 검토 | 공개 통계와 규칙으로 만든 페르소나의 현실성을 확인할 절차가 없음 | Persona Survey 합성 응답 275건을 공개 통계와 대조하고, 기준에 맞지 않는 응답은 평가에서 제외 |
| 가정 값 | 주당 가용 시간, 팀 상황, 시험 기간 행동은 근거 자료 없는 가정 | 팀 없이 시작, 시험 기간 중단 경향은 가정과 같은 방향. 주당 가용 시간은 가정보다 낮음(중앙값 8시간, 가정 19시간) |
| 예외 사례 | 팀이 만든 경계 사례 8개 유형(학생 조건 중심) | Ready for Agent 예외 사례 297건(마감 일정 88건, 제출물 47건, 참가 자격 44건, 팀 구성 33건 등) |
| 문제 발견 | 기존 규칙의 누락 여부를 알기 어려움 | 규칙 문서에 추가할 상황 11건, 동작 보완 4건 확인 |

- **Persona Survey**: 공모전 경험률이 96%로 공개 조사(39.9%)와 차이가 커서, 사전에 정한 기준에 따라 응답을 평가 데이터에 넣지 않고 가정 점검 자료로만 썼습니다.
- **Ready for Agent**: 서비스 규칙 문서 하나를 넣어 예외 사례 297건과 질문 320건을 받았습니다. 개선 후에는 같은 사례로 개선 전후 통과율을 비교할 계획입니다.

## 사용자 검증(UT)

서울 4개 대학 학부생 7명이 공고 입력부터 결과와 계획 확인까지 직접 사용하고 설문에 응답했습니다. 확인한 불편 5가지를 기능과 화면에 반영했습니다.

| 영역 | 확인한 불편 | 반영한 개선 |
|---|---|---|
| 온보딩 | 첫 접속 시 입력 항목이 많아 결과를 예측하기 어려움 | 첫 화면에 샘플 분석 결과 제공 |
| 차별성 | 일반 AI 답변과의 차이를 체감하기 어려움 | 개인화 OFF/ON 비교 화면 추가 |
| 실행력 | 주차별 계획이 실제 수업·아르바이트 일정과 충돌 | 시간표 사진에서 공강과 가용 시간을 읽어 일정 배치 |
| 접근성 | 설치 없이 개인 기기에서 바로 써 볼 방법이 필요 | 웹 주소로 접속해 바로 사용 |
| 안정성 | 분석 결과가 출력되지 않는 오류 | 다른 모델로 즉시 전환하고 자동 재시도 |

## 실행

최종 서비스는 `backend/`입니다. Python 3.10 이상이 필요합니다.

```bash
cd backend
pip install -r requirements.txt
export GEMINI_API_KEY=...     # 키는 코드나 저장소에 넣지 않는다
python app.py                 # http://localhost:5000
```

| 환경변수 | 설명 |
|---|---|
| `GEMINI_API_KEY` | 필수. Google Gemini API 키 |
| `SECRET_KEY` | 로그인 세션 암호화 키. 배포 때 반드시 바꾼다 |
| `COOKIE_SECURE` | https로 배포할 때 `1` |
| `MODEL` | 기본 `gemini-4-hydrogen` |
| `DB_PATH` | 계정과 기록을 저장할 SQLite 파일. 기본 `backend/fourdo.db`(커밋하지 않음) |
| `PORT` | 기본 `5000` |

## 저장소 구조

| 경로 | 내용 |
|---|---|
| `backend/app.py` | 최종 서비스 서버. 공고 읽기, Gemini 호출, 날짜·가용 시간 계산, 로그인과 내 도전 기록 |
| `backend/static/` | 화면(입력, 결과, 실행 계획, 하루별 할 일, 개인화 비교, 내 도전 기록) |
| `demo/`, `src/aihack4/`, `scripts/`, `tests/` | 초기 프로토타입 PODO(참여 가능 여부 판정 엔진, 공고 수집, Streamlit 데모). 최종 서비스에서는 쓰지 않음 |
| `data/test/`, `data/results/` | 프로토타입 검증용 합성 데이터와 결과 |
| `docs/` | 기획 문서, 멘토링 자료, API 응답 예시 |

루트의 `pyproject.toml`, `requirements.txt`, `.env.example`, `.streamlit/`은 프로토타입의 실행 환경입니다. 최종 서비스는 `backend/requirements.txt`만 쓰면 됩니다.
