# FourDo 백엔드 설계 v3 (2026-11-15)

화면(프론트)은 그대로 두고 백엔드를 다시 짠다. 이전 버전의 문제: 결과가 뻔함, 로드맵이 비현실적, 개인화가 숫자(시간·판정)에서만 보임, LLM 호출이 많아 느림.

## 1. 핵심 결과

**내 맞춤 전략 + 로드맵.** 참여 가능 여부는 맨 위에 짧게 확인만 한다.
개인화 = 같은 공고라도 **사람마다 할 일 자체가 달라진다.**

- 전략의 중심: **A. 제출물별 만드는 방법**, **B. 결과물 범위**(최소/표준/차별화)
- C. 강점 포인트: 공고에 평가 기준이 있을 때만 덧붙인다
- E. 위험 대비: 로드맵 안에 녹인다(시험 전에 끝내기 등)
- D. 부문 선택: 나중에

## 2. 원칙: LLM은 선택지를 만들고, 코드가 고른다

```
[LLM 1회] 공고 → 공고 카드 (학생과 무관 → 공고마다 한 번, 재사용)
   ├ 기본: 제목, 주최, 마감(시각), 팀 인원
   ├ 자격 조건: 지역·학교·신분·나이·전공·기타 (원문 근거)
   ├ 평가 기준: 항목·배점 (있으면)
   └ 제출물(만드는 순서대로)마다 선택지 2~3개
        선택지 = 방법 이름, 단계(최소/표준/차별화), 필요 역량(7개 목록 안)·수준,
                 단계별 작업(이름·시간), 구체적인 방법 설명, 원문 근거 문장
        규칙: 제출물마다 '누구나 할 수 있는' 선택지를 최소 하나

[코드] 공고 카드 + 프로필 → 결과 (즉시, LLM 없음)
   1. 자격 비교 (모르는 조건은 예/아니오 질문)
   2. 가용 시간 (주당 시간, 바쁜 일정, 시간표)
   3. 제출물마다 할 수 있는 선택지 걸러내기 (본인 또는 팀원 역량·수준)
   4. 목표로 고르기 (수상 → 가장 높은 단계, 경험 → 표준)
   5. 시간이 모자라면 아끼는 시간이 큰 것부터 한 단계씩 낮추기
   6. 판정
   7. 로드맵 배치
```

- 역량 수준이 모자라면 그 선택지는 고르지 않고 아래 단계로 간다(배우는 시간은 추정 근거가 약해 선택지로 두지 않는다).
- 표준으로 안 되면 '준비하면 가능'(최소 단계로 짬), 최소로도 안 되면 '어려움'.
- 재판정·다시 짜기·프로필 수정은 공고 카드를 재사용해 코드만 다시 돈다.

## 3. 입력

| 입력 | 쓰임 |
|---|---|
| 공고 링크·본문 | 공고 카드. 링크는 페이지와 첨부파일(PDF·HWP)만 읽고, 내용이 짧으면 본문 붙여넣기 안내 |
| 역량 7개 + 수준 | 기획, 디자인, 개발, 데이터·AI, 영상, 발표, 글쓰기 × 입문/가능/능숙. **LLM 선택지도 같은 목록** |
| 팀 상태 + 팀원 역량 | 팀이 있을 때만 팀원 역량 칩. 팀원 역량도 선택지 고르기에 쓴다 |
| 주당 시간, 바쁜 일정, 시간표 | 가용 시간, 범위 고르기, 배치 |
| 학교·지역·신분·나이, 학년·전공 | 자격 비교 |
| 목표 | 경험 쌓기(표준) / 수상(가장 높은 단계) |
| 관련 경험(자유 입력) | 보조 정보만 |

## 4. 로드맵 배치 (코드)

- 제출물은 공고 카드의 순서대로, 각 제출물은 고른 선택지의 단계별 작업 순서대로 놓는다.
- **고르게**: 필요한 시간을 여유 기간 전까지 고르게 나눈다(적어 낸 시간을 매일 꽉 채우지 않는다).
- 한 번 작업은 최소 1시간. 못 쓰는 날(시험 등)은 건너뛴다.
- 마감 전 여유 기간(전체의 10%, 최소 1일)에는 최종 점검·제출만.
- 제출물이 끝나는 날 = 중간 목표("12/3까지 기획서 완성").
- 하루별 할 일은 수업을 피해 시간대에 배치. 끝낸 작업을 체크하면 같은 규칙으로 다시 배치.

## 5. 화면에 나가는 것

| 화면 | 내용 |
|---|---|
| 결과 | 판정 한 줄, 내 전략(제출물별 고른 방법과 이유), 자격 질문, 이번 주 할 일·다음 중간 목표 |
| 실행 계획 | 주차별 작업과 중간 목표, 한 단계 낮출 때 줄어드는 시간 |
| 하루별 할 일 | 날짜별 수업과 할 일, 체크 후 다시 짜기 |
| 개인화 비교 | **같은 엔진 OFF/ON**: 프로필 없이 고른 결과(표준, 시험 모름) vs 내 결과. 차이는 코드가 찾아 설명 |
| 신뢰도 | 새 엔진으로 다시 잴 때까지 '측정 전' |

## 6. 근거

- 선택지마다 원문 근거 문장(코드가 원문에 실제로 있는지 확인)
- 선택 이유는 코드가 붙인다("영상 입문 → 화면녹화+자막", "가용 23h < 필요 30h → 한 단계 낮춤")
- 평가: 공고 카드 추출(사람 검수), 선택·배치(회귀 검사), 판정(사람 라벨)을 나눠 잰다
